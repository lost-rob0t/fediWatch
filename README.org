#+title: fediWatch

* About

=fediWatch= is a Nim 2 StarIntel actor that monitors Mastodon instances or
accounts and emits strict StarIntel 0.9 document envelopes.

Each status produces:

- a =user= document;
- a =social-media-post= document;
- an =authored= relation;
- for boosts, a =reposted= relation instead of falsely attributing the original
  post content to the boosting account.

Output is selectable at runtime:

- StarIntel HTTP =POST /documents/bulk=;
- RabbitMQ topic exchange =documents= with routing keys
  =documents.ingest.<dtype>=.

* Requirements

- Nim 2.2 or newer;
- a Mastodon-compatible API;
- =rabbitmq-c= development headers and library for native builds;
- either starintel-server HTTP access or RabbitMQ access.

On Debian or Ubuntu:

#+begin_src shell
sudo apt-get install librabbitmq-dev
#+end_src

The included Nix shell provides Nim, OpenSSL, =rabbitmq-c=, and a local
RabbitMQ server.

* Build

#+begin_src shell
nimble install -y
nimble buildRelease
#+end_src

Run tests:

#+begin_src shell
nimble test -y
#+end_src

* Targets

Targets can be loaded from inline JSON, a local JSON file, or the StarIntel
HTTP API.

** Inline targets

#+begin_src shell
export FEDIWATCH_TARGETS='[
  {
    "target": "https://mastodon.social",
    "dataset": "fediverse",
    "options": {
      "type": "instance",
      "local": true,
      "limit": 40
    }
  },
  {
    "target": "alice@example.social",
    "dataset": "fediverse",
    "options": {
      "type": "account",
      "exclude_reblogs": true
    }
  }
]'
#+end_src

** StarIntel 0.9 target document

#+begin_src json
{
  "_id": "target-fediwatch-example",
  "dataset": "fediverse",
  "dtype": "target",
  "schema_version": "0.9.0",
  "version": 1,
  "date_added": "2026-07-30T00:00:00.000Z",
  "date_updated": "2026-07-30T00:00:00.000Z",
  "sources": [],
  "evidence": [],
  "data": {
    "actor": "fediwatch",
    "target": "https://mastodon.social",
    "target_type": "instance",
    "options": [
      {"key": "local", "value": true},
      {"key": "limit", "value": 40}
    ]
  }
}
#+end_src

Supported target sources:

| Variable | Meaning |
|----------+---------|
| =FEDIWATCH_TARGETS= | Inline JSON object or array |
| =FEDIWATCH_TARGETS_FILE= | Path to a JSON object or array |
| =FEDIWATCH_TARGETS_URL= | HTTP endpoint returning targets |

When none are set, fediWatch requests
=STARINTEL_HTTP_URL/targets/fediwatch=.

* HTTP bulk output

#+begin_src shell
export FEDIWATCH_TRANSPORT=http
export STARINTEL_HTTP_URL=http://127.0.0.1:5000
# Optional explicit override:
# export STARINTEL_HTTP_BULK_URL=http://127.0.0.1:5000/documents/bulk
# export STARINTEL_HTTP_TOKEN=...
#+end_src

The actor splits output into batches of at most 500 documents and rejects
partial bulk failures.

* RabbitMQ output

#+begin_src shell
export FEDIWATCH_TRANSPORT=rabbitmq
export STARINTEL_RABBITMQ_URL=amqp://guest:guest@127.0.0.1/
export STARINTEL_RABBITMQ_EXCHANGE=documents
export STARINTEL_RABBITMQ_ROUTING_PREFIX=documents.ingest
#+end_src

Both =amqp://= and =amqps://= URLs are supported. AMQPS uses the operating
system CA store and verifies both the certificate chain and broker hostname.
Percent-encode credentials and virtual hosts when needed, for example
=amqps://actor:p%40ss@rabbit.example/%2Fstarintel=.

The RabbitMQ path uses a small Nim binding over the maintained =rabbitmq-c=
library rather than the obsolete Nim package that previously broke dependency
installation. Messages are persistent JSON with the document type included in
both the AMQP type property and routing key.

* Runtime configuration

| Variable | Default |
|----------+---------|
| =FEDIWATCH_TRANSPORT= | =http= |
| =FEDIWATCH_POLL_INTERVAL_SECONDS= | =60= |
| =FEDIWATCH_BATCH_SIZE= | =500= |
| =FEDIWATCH_EMIT_RETRIES= | =3= |
| =FEDIWATCH_ONCE= | =false= |
| =STAR_DATASET= | =fediverse= |
| =STARINTEL_SCHEMA= | unset; set to validate every document against the canonical schema |
| =FEDIWATCH_LOG= | unset; stdout only |
| =HTTP_PROXY= / =HTTPS_PROXY= | unset |

Per-target options include =auth=, =proxy=, =ua=, =since_id=, =local=,
=remote=, =only_media=, =exclude_replies=, =exclude_reblogs=, and =limit=.

* Delivery behavior

The newest Mastodon status cursor is committed only after the entire generated
batch is accepted by the selected StarIntel transport. Failed emissions are
retried and then replayed on the next poll, providing at-least-once delivery.
Document IDs are deterministic so CouchDB conflicts remain idempotent.
